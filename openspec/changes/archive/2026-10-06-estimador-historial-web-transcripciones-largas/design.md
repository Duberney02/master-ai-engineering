# Design

## Context

`POST /api/v1/estimate` valida `EstimationRequest` (descripción 20–2000), ejecuta `EstimationPipeline` (guardrails → caché exacta → caché semántica → generación validada) y devuelve `{result, prompt_version, cached}`. No existe persistencia: solo Redis con TTL. Los clientes son Streamlit y `sse_demo.html`. `estimador-cag/docker-compose.yml` levanta API, chat y Redis Stack para desarrollo.

## Goals / Non-Goals

**Goals:**
- Aceptar transcripciones de hasta 80 000 caracteres sin degradar guardrails ni cachés.
- Historial durable y consultable sin acoplar la disponibilidad de la estimación a PostgreSQL.
- Aplicación web Rails independiente que solo habla HTTP con la API.
- Un único `docker compose up` desde la raíz.

**Non-Goals:**
- Autenticación, multiusuario o borrado/edición del historial.
- Migraciones con Alembic (ver decisión 3).
- Streaming token a token en la web (se usa `/estimate`, no el stream).
- Migraciones de esquema: una base creada antes de añadir `metrics` necesitaría añadir la columna a mano.
- Cambiar el flujo `/api/v1/transcription/*`.

## Decisions

1. **Límite de 80 000 caracteres como constante compartida.** `MAX_DESCRIPTION_CHARS = 80_000` y `MIN_DESCRIPTION_CHARS = 20` en `app/schemas/project_estimation.py`; Streamlit importa la constante y no repite el número. Los 80 000 caracteres equivalen a unos 20 000 tokens, dentro del contexto de los modelos configurados. La caché exacta usa SHA-256 del cuerpo y no se ve afectada.
2. **Textos largos en guardrails y caché semántica.** Los detectores locales son regex lineales y se ejecutan sobre el texto completo. La moderación envía una lista de tramos de hasta 30 000 caracteres en una sola llamada (`input=[...]`) para no depender de un límite de entrada no documentado. La caché semántica se omite (consulta y almacenamiento) si `len(semantic_text) > SEMANTIC_CACHE_MAX_CHARS` (por defecto 8 000, ≈2 000 tokens): `text-embedding-3-small` admite 8 191 tokens y truncar produciría aciertos falsos entre transcripciones con el mismo inicio. Se registra `semantic_cache_skipped` con la razón `text_too_long`.
3. **PostgreSQL con SQLAlchemy 2 asíncrono y `asyncpg`.** Una tabla `estimations` (`id` entero autoincremental, `description` Text, `options` JSON con tipo de proyecto, nivel, formato y referencias, `result` JSON, `metrics` JSON nulable, `prompt_version`, `cached`, `cache_source`, `model`, `provider`, `requested_at`, `completed_at` con zona horaria). `JSON` genérico con variante `JSONB` en PostgreSQL permite probar con SQLite (`aiosqlite`) sin servidor. El esquema se crea con `metadata.create_all` (idempotente) en el primer uso; se descarta Alembic porque hay una sola tabla y ninguna migración previa. Alternativa descartada: `psycopg` con SQL a mano (más código de mapeo y sin sustituto ligero en pruebas).
4. **Persistencia tolerante a fallos.** `EstimationHistory.save` captura cualquier excepción, la registra sin datos del usuario y devuelve `None`; la estimación se responde igualmente con `estimation_id=null`. Sin `DATABASE_URL` el servicio está desactivado: `save` no hace nada y la lectura responde 503 `{"detail": "History is not configured"}`. Los errores de lectura de base de datos responden 503 saneado.
5. **Procedencia de caché.** `PipelineOutcome.cache_source` ∈ {`none`, `exact`, `semantic`}; `cached` se mantiene (`cache_source != "none"`). `EstimationResponse` añade `cache_source`, `estimation_id` y `metrics`; `EstimationStreamMetadata` añade `cache_source` y `estimation_id`. `CallMetrics` (modelo, proveedor, finalización, uso, latencia, acierto de caché y costes) es la base de `EstimationStreamMetadata` y se obtiene con `PipelineOutcome.metrics()`; el historial la guarda en la columna `metrics`, y un registro sin ella devuelve `metrics=null`. El router guarda tras el pipeline, también en el stream, antes de emitir `result`.
6. **Endpoints de historial en un router propio.** `GET /api/v1/estimations?limit=` (1–50, por defecto 10, orden `requested_at` descendente) devuelve elementos resumidos (`id`, `requested_at`, `project_type`, `detail_level`, `output_format`, `prompt_version`, `cache_source`, `confidence_pct`, `total_cost_eur`, `total_duration_weeks`, `out_of_scope`, `description_excerpt` de 200 caracteres). `GET /api/v1/estimations/{id}` devuelve el registro completo con `description` y `result`; un id inexistente es 404. `get_history` es una dependencia inyectable sustituible con `dependency_overrides`.
7. **Rails + Faraday (`estimator-web/`).** Aplicación Rails minimalista sin Active Record ni JavaScript empaquetado (el temporizador y el contador son un `<script>` inline). `EstimatorApi` envuelve Faraday con URL base `ESTIMATOR_API_URL`, `open_timeout` 5 s y `read_timeout` configurable (por defecto 300 s) y traduce a `EstimatorApi::Error` (con `message` en español y `status`): conexión/timeout → «No se pudo conectar con la API», 400 → `message` del guardrail, 422 → «La solicitud no es válida», 404 → no encontrado, 5xx → mensaje genérico; nunca se muestra el cuerpo crudo. Un objeto de formulario `ActiveModel` valida longitud (20–80 000) y el archivo `.txt` (extensión, UTF-8 válido, tamaño máximo 400 KB). El POST llama a `/api/v1/estimate`; con `estimation_id` redirige a `/estimations/:id` y sin él (historial desactivado) renderiza el resultado directamente. Pruebas con Minitest y WebMock, sin API real.
8. **Barra lateral de la web.** Rails no tiene las plantillas Jinja2, así que `GET /api/v1/prompts/estimation?prompt_version=&project_type=&detail_level=&output_format=` (router `prompts`) devuelve `{prompt_version, system_prompt, examples[]}` renderizando con una descripción de vista previa (el prompt de sistema no incluye la descripción); `few_shot_examples` se movió de `streamlit_support` a `app/prompts/loader.py` y Streamlit lo sigue importando desde su módulo. `estimator-web` pinta en `aside#sidebar` el prompt (solo lectura), los ejemplos y las métricas del campo `metrics` de la estimación mostrada; el prompt corresponde a las opciones de esa estimación (en el formulario, a las opciones por defecto). Es informativa: si la API falla se muestra un aviso y la página sigue. Un botón la oculta. No se replica «Borrar historial» de Streamlit: el historial de la web es persistente y borrarlo es un no-objetivo.
9. **Streamlit (equivalencia).** `streamlit_app.py` importa `MAX_DESCRIPTION_CHARS`, ofrece `st.file_uploader(type="txt")` que sustituye la descripción, y muestra el tiempo transcurrido al terminar; el spinner existente es el indicador de carga.
10. **Compose raíz.** `docker-compose.yml` en la raíz con servicios `estimador-cag`, `estimador-cag-chat` (mismo imagen que la API, ejecuta `streamlit run` con `ESTIMATOR_API_BASE_URL` y sin claves), `estimator-web`, `redis` (Redis Stack), `postgres` (`postgres:17-alpine`) y red `estimator-net`. Volúmenes con nombre `redis_data` y `postgres_data`. Healthchecks: `pg_isready`, `redis-cli ping`, `/health` de la API, `/_stcore/health` de Streamlit y `/up` de Rails; cada servicio espera con `depends_on: condition: service_healthy`. La API lee las claves de `estimador-cag/.env` (`env_file` obligatorio) y sobrescribe `REDIS_URL` y `DATABASE_URL` hacia los servicios internos. Solo se publican los puertos de la API (8000), el chat (8501) y la web (3000); la contraseña de PostgreSQL se parametriza (`POSTGRES_PASSWORD`, con valor de desarrollo por defecto). El Compose de `estimador-cag/` se conserva para desarrollo del backend.
11. **Validación con Docker.** No hay Python ni Ruby fiables en el host: las suites se ejecutan en contenedores (`uv run pytest` con la imagen de uv, `bin/rails test` con la imagen de Ruby) y el stack completo se levanta con Compose para comprobar healthchecks y la prueba de integración con PostgreSQL real.

## Risks / Trade-offs

- [Transcripciones largas tardan más y cuestan más tokens] → el temporizador y el indicador lo hacen visible; el `read_timeout` de Faraday es de 300 s y el de Streamlit de 600 s.
- [`create_all` no evoluciona esquemas] → aceptable con una tabla; si cambia se introducirá Alembic en otro cambio.
- [Omitir la caché semántica en textos largos reduce aciertos] → la caché exacta cubre repeticiones idénticas, que es el caso típico de una transcripción.
- [Historial con transcripciones completas puede contener datos sensibles] → los guardrails ya rechazan PII antes de guardar; el volumen es local y no se expone sin autenticación (Non-Goal explícito).
